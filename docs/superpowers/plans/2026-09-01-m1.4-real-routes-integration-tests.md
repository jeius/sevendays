# M1.4 — Real API Routes + Integration Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the stub API with real Drizzle-backed routes mounted under `/api/v1` (thin handlers over service modules, uniform error shape, price snapshots, server-side lookup resolution) and prove them with integration tests against real Postgres (docker compose locally, CI service container, migrations in global setup, fail-loud on unreachable).

**Architecture:** `apps/api` composes a root app that mounts a `/api/v1` sub-app holding the four domain routers; each router delegates to a service module owning its Drizzle queries. Shared Zod read/create shapes live in `packages/types`; the db client is built from the pooled `DATABASE_URL` (ADR-0007, `prepare: false`). Tests run against compose Postgres 17 through the composed app's HTTP boundary (prior art: `apps/api/src/index.test.ts`), serial files, truncate-between-tests, minimal hand-written fixtures — the compose database is never catalog-seeded.

**Tech Stack:** Hono ^4.6 + @hono/zod-validator (Zod v4), Drizzle ORM ^0.45.2 via `@sevendays/db` (dist — run `pnpm build:packages` first), drizzle-orm/postgres-js migrator for programmatic apply, vitest ^4.1.11 (node env, explicit include per ADR-0003), docker compose v5.5 (daemon verified running 2026-09-01), Node >= 24.

**Spec:** `docs/specs/2026-08-30-m1-real-data-layer-spec.md` (the M1 spec with its **M1.4 revision block, 2026-09-01, grill Q1–Q11** — the authoritative decisions this plan implements) + full draft `.scratch/m1.4-real-routes/spec.md`. Ticket: **#6**. ADRs to author in-plan: **0008** (integration tests vs real Postgres), **0010** (URL path versioning). Live reference facts verified 2026-09-01: live Supabase is **PG 17**; `worker-configuration.d.ts` carries optional `DATABASE_URL`; both existing routes are stubs at `apps/api/src/routes/{branches,appointments}.ts`; `packages/db` resolves from `dist/`; no compose file exists yet; CI has no service container.

## Global Constraints

- **Versioning contract (Q10/Q11):** public surface mounts under `app.route('/api/v1', api)`; `/health` stays top-level; URL-prefix only; additive-only within v1 (new fields/params optional/defaulted); never remove response fields within v1.
- **Uniform error shape (Q4):** every failure — Zod validation, unresolvable/inactive reference, db error — returns `c.json({ error }, status)` (never bare `c.notFound()`); shape formalized as `apiErrorSchema { error: string, details?: unknown }` in `packages/types` and asserted in tests.
- **No fabricated data:** never seed or hardcode the real catalog into tests; fixtures are minimal hand-written rows (compose db never catalog-seeded); never trust client-supplied prices — snapshots are server-written.
- **Active-row refs (Q5):** Service Package and Add-on Service references must resolve to **active** rows; Branch must exist (no is_active column exists on branches); unresolvable → 400 with per-entity message.
- **Real Postgres only (ADR-0008):** no db mocks anywhere in the suite; unreachable db fails loud with "start the compose db"; tests never read the Supabase env.
- **Migration mechanics:** migrations come from `packages/db/migrations` via the new `./migrate` export — never hand-edit migration files; global setup applies 0000+0001 before any test; clean-slate TRUNCATE in setup guards crashed-run leftovers.
- **Biome-clean commits:** `pnpm exec biome check --write <files>` before every commit (M1.3 ruling; biome scripts call the `biome` bin, never pnpx).
- **Fresh-clone bootstrap precedes gates:** `pnpm install && pnpm build:packages` before typecheck/tests anywhere in the session.
- **`pnpm check` + `pnpm build` green before any commit lands final** (ticket #6 gate); final tasks re-run the full gate.
- **Commit conventions:** unscoped conventional subjects (`feat:`, `test:`, `docs:`, `chore:`), bullet bodies when wordy; user commits/pushes final state — the plan commits locally on the feature branch only; branch name `feat/m1.4-real-routes-integration-tests`.
- **Zod v4 style:** top-level `z.uuid()`/`z.email()`, `.safeParse` in tests, no `noUncheckedIndexedAccess` violations (no `!` assertions; guard destructures).
- **Vitest gotcha (ADR-0003):** `apps/api`'s own `vitest.config.ts` stays the runner config; after any change, run the workspace suite directly and confirm test count > 0.

```ts
import { migrate } from 'drizzle-orm/postgres-js/migrator';
import postgres from 'postgres';
import { fileURLToPath } from 'node:url';

export const defaultMigrationsFolder = fileURLToPath(new URL('../migrations', import.meta.url));

/**
 * Programmatic migration apply for test global setup (ADR-0008): opens its
 * own postgres-js client (prepare:false — session-pooler compatible), runs
 * the drizzle migrator over packages/db/migrations, and closes the client.
 * Never hand-edit packages/db/migrations — generated via db:generate only.
 */
export async function migrateDatabase(
  connectionString: string,
  opts?: { migrationsFolder?: string }
): Promise<void> {
  const client = postgres(connectionString, { prepare: false });
  try {
    await migrate(client, { migrationsFolder: opts?.migrationsFolder ?? defaultMigrationsFolder });
  } finally {
    await client.end({ timeout: 5 });
  }
}
```

```ts
import postgres from 'postgres';

const DEFAULT_TEST_DB = 'postgres://postgres:postgres@localhost:5432/sevendays_test';

export async function setup(): Promise<() => Promise<void>> {
  const url = process.env.TEST_DATABASE_URL ?? DEFAULT_TEST_DB;
  process.env.TEST_DATABASE_URL = url;

  const ping = postgres(url, { prepare: false, connect_timeout: 5, max: 1 });
  try {
    await ping`select 1`;
  } catch (err) {
    console.error(
      `\n[integration-tests] Test database unreachable at ${url}.\n` +
        'Start the compose db:  docker compose up -d db\n' +
        `Underlying error: ${(err as Error).message}\n`
    );
    process.exit(1);
  } finally {
    await ping.end({ timeout: 5 });
  }

  const { migrateDatabase } = await import('@sevendays/db/migrate');
  await migrateDatabase(url);

  const { createTestDb } = await import('./helpers/db.js');
  const { truncateAll } = await import('./helpers/truncate.js');
  await truncateAll(createTestDb(url));

  return async () => {
    // no teardown: leave the compose volume clean (crashed-run leftovers are

  };
}
```

- [ ] **Step 1: Write ADR-0008** "Integration tests against real Postgres" — Context: M1's seam ruling; why mocks at the db boundary were rejected (a mocked query builder can't catch a wrong column name — precisely M1's bug class); Decision: one test seam (composed app's HTTP boundary), real Postgres via compose (PG 17, matching live Supabase's major) locally + CI service container, migrations-before-tests via the db package's `migrateDatabase` subpath export in global setup, fail-loud on unreachable ("start the compose db"), tests never read the Supabase env, serial files + truncate-between-tests, minimal hand-written fixtures (compose never catalog-seeded — seed fidelity stays proven by `db:verify-seed` against the live db). - [ ] **Step 2: Write ADR-0010** "URL path versioning" — Context: unversioned `/api/*` with zero frontend consumers is the last free moment; M2's api-client will freeze the base path. Decision: URL-prefix versioning — `app.route('/api/v1', api)`; `/health` stays top-level (infra, not a versioned surface); no version header. Contract: additive-only within v1 (new fields/params optional/defaulted so Zod clients never break); breaking changes ship under `/v2` with v1 serving until deprecation; response fields are never removed within a version. Alternatives: header-based versioning (rejected — the api-client keys off the base URL path; a header adds a protocol dimension to thread); deferring to M2 (rejected — costs a rename migration after consumers exist). Consequences: every future public endpoint mounts inside the v1 router; the M2 pre-flight consumes `/api/v1/*` as-is.
