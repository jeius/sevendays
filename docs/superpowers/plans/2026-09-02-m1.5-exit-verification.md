# M1.5 — M1 Exit Verification + Close-Out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Execute Milestone 1's exit gate against the deployed Worker and the live Supabase database — create an Appointment through the deployed API, prove the row in Postgres directly, redeploy and prove it survived, negative-control the deployed error shape, clean the verification row up — and close Milestone 1 out (#7 + #2, roadmap tick, progress refresh).

**Architecture:** No product code changes. One new committed probe script in `packages/db/scripts/` (sibling of `db-state.mjs`, same secret-safety posture) provides psql-equivalent row confirmation and flag-gated single-row deletion; one throwaway rehearsal fixture driver proves the probe against compose Postgres before it ever touches the live DB. The verification sequence itself is an operational runbook: pre-flight audit → Act 1 create → Act 2 confirm → Act 3 user redeploy + survival + list read-back → Act 4 negative controls → evidence recorded → row deleted. Deploys and secret operations are user-run; the agent runs everything else.

**Tech Stack:** Node >= 24, postgres.js ^3.4.9 (already a `packages/db` dependency), Hono ^4.6 served by the deployed Cloudflare Worker `sevendays-api`, wrangler 4.127.1, Turborepo + pnpm 11, compose Postgres 17 (existing `compose.yaml`), Zod v4 (already in `packages/types`).

**Spec:** `.scratch/m1.5-exit-verification/spec.md` (Q1–Q5, 2026-09-02, all as-recommended) under the governing M1 spec `docs/specs/2026-08-30-m1-real-data-layer-spec.md` (its Further Notes define the verification protocol this plan executes). ## Global Constraints

- **Deploys and secrets are user-run.** The agent never runs `wrangler deploy` or `wrangler secret put`; it prepares everything, hands over with the exact command, and verifies the result afterward. Everything else (curl, probes, docs, PR) is agent-run.
- **Connection strings never enter chat or committed output.** The probe prints derived facts only (ports, counts, row fields, verdicts) — never a URL. It reads the same gitignored files as its siblings (`packages/db/.env` → `DATABASE_MIGRATE_URL`, session-mode pooler per ADR-0007).
- **Q1=A — psql-equivalence:** row confirmation goes through the committed probe script (repo precedent: `db:verify-seed` is psql-equivalent). No psql install.
- **Q2=A — deployed surface only:** every verification HTTP call targets the deployed Worker's public URL. Local `wrangler dev` is never a verification surface.
- **Q3=A — evidence before deletion:** the verification row is deleted only after all evidence (POST response, probe tables, negative-control bodies, redeploy confirmation) is recorded in `docs/progress.md`. Deletion is single-row, flag-gated.
- **Q4=B — negative controls characterize the final artifact:** they run against the Worker that remains deployed (after Act 3's redeploy). Non-400 or a bare not-found body is a blocking finding → fix on this branch → user redeploys → sequence re-runs.
- **Q5=A — the PR closes #7 and #2** (`Closes #7`, `Closes #2` in the body); auto-close at merge per the M1.4 precedent.
- **Expected 201 shape (from `packages/types/src/appointment-read.ts`):** the POST returns the appointment record **plus** `addonServices: [{ addonServiceId, name, priceCents }]`. Snapshot values (`packagePriceCents`, per-add-on `priceCents`) are server-written; the probe and the runbook assert them, never trust them as input.
- **Uniform error shape:** every failure is `{ error: string, details?: [...] }` with status 400/500 — never Hono's plain-text default. Zod validation failures carry `error: "Invalid request payload."` + per-issue `details`; unresolvable Service Package reference carries `error: "Unknown servicePackageId."`; unresolvable Add-on reference carries `error: "Unknown addonServiceId."` (exact strings from `apps/api/src/routes/appointments.ts` REASON_MESSAGES). Assert the **shape** (error string, details array, status), never incidental details.
- **Vocabulary:** Appointment (never booking/order/reservation), Add-on Service (never extra/service unqualified), Kind, Status, Service Package, Branch — per `apps/api/CONTEXT.md` Avoid lines. The gate verifies the M1.4 contract (ADR-0010 `/api/v1` surface).
- **TDD scope:** Task 1 (the probe) is test-driven against compose Postgres. Tasks 2–7 are operational verification and close-out — they are verified by running for real (M1 spec's ruling on operational tooling), with explicit expected outputs.
- **Feature branch:** `feat/m1.5-exit-verification`, branched from current `main` (894d1c1). The user commits/pushes final state; the plan commits locally on the feature branch only.
- **Biome-clean commits:** `pnpm exec biome check --write <files>` before every commit; biome scripts call the `biome` bin, never pnpx.
- **Fresh-clone bootstrap precedes gates:** `pnpm install && pnpm build:packages` before typecheck/tests anywhere in the session.
- **`pnpm check` + `pnpm build` green before the PR opens** (repo gate).
- **Zod v4 style:** top-level `z.uuid()`/`z.email()`; no non-null `!` assertions (guard destructures); `.safeParse` in tests.
- **Vitest gotcha (ADR-0003):** each workspace runs its own config; after touching db-package tests, run `pnpm --filter @sevendays/db test` directly and confirm test count > 0.

```js
// psql-equivalent Appointment row probe (M1.5, Q1=A). Prints derived facts
// only — never a connection string. Modes:
//   confirm <appointmentId>  — assert the row + add-on join rows against
//                              expectations read from stdin (JSON)
//   delete  <appointmentId>  — delete the single row, re-assert absence
//   absent  <appointmentId>  — assert the row is gone
// Exit 0 = verified; exit 1 = mismatch/missing/error. Run from packages/db:
//   node --env-file=.env scripts/verify-appointment-row.mjs confirm <id>
import postgres from 'postgres';

const url = process.env.DATABASE_MIGRATE_URL;
if (!url) {
  console.error('DATABASE_MIGRATE_URL is not set (run scripts/check-env.mjs)');
  process.exit(1);
}

export async function assertAppointmentRecord(sql, expected) {
  const rows = await sql`
    select id, branch_id, service_package_id, customer_name, customer_email,
           customer_phone, scheduled_at, status, kind, package_price_cents,
           notes, created_at, updated_at
    from appointments
    where id = ${expected.id}`;
  const row = rows[0];
  if (!row) return { ok: false, reason: 'not_found' };

  const addons = await sql`
    select a.addon_service_id, s.name, a.price_cents, a.created_at
    from appointment_addon_services a
    join addon_services s on s.id = a.addon_service_id
    where a.appointment_id = ${expected.id}
    order by a.created_at`;

  const checks = [];
  const push = (label, dbValue, expectedValue) => {
    checks.push({ label, ok: String(dbValue) === String(expectedValue) });
  };
  push('id', row.id, expected.id);
  push('branchId', row.branch_id, expected.branchId);
  push('servicePackageId', row.service_package_id, expected.servicePackageId);
  push('customerName', row.customer_name, expected.customerName);
  push('customerEmail', row.customer_email, expected.customerEmail);
  if (expected.customerPhone !== undefined) {
    push('customerPhone', row.customer_phone, expected.customerPhone);
  }
  push('kind', row.kind, expected.kind);
  push('status', row.status, expected.status);
  push('packagePriceCents', row.package_price_cents, expected.packagePriceCents);
  if (expected.scheduledAt !== undefined) {
    const dbIso = row.scheduled_at instanceof Date ? row.scheduled_at.toISOString() : String(row.scheduled_at);
    const expIso = new Date(expected.scheduledAt).toISOString();
    push('scheduledAt', dbIso, expIso);
  }

  const expectedAddons = expected.addonServices ?? [];
  push('addonCount', addons.length, expectedAddons.length);
  for (let i = 0; i < Math.min(addons.length, expectedAddons.length); i += 1) {
    push(`addon[${i}].addonServiceId`, addons[i].addon_service_id, expectedAddons[i].addonServiceId);
    push(`addon[${i}].name`, addons[i].name, expectedAddons[i].name);
    push(`addon[${i}].priceCents`, addons[i].price_cents, expectedAddons[i].priceCents);
  }

  const failed = checks.filter((c) => !c.ok);
  for (const c of checks) {
    console.log(`${c.ok ? '[ok]' : '[MISMATCH]'} ${c.label}`);
  }
  console.log(
    failed.length === 0
      ? `CONFIRM: PASS — appointment ${expected.id} matches every expected value (${checks.length} checks)`
      : `CONFIRM: FAIL — ${failed.length} mismatch(es)`
  );
  return { ok: failed.length === 0, row, addons, failed };
}

export async function deleteAppointmentRow(sql, id) {
  const result = await sql`
    delete from appointments where id = ${id} returning id`;
  const deleted = result.length === 1;
  console.log(deleted ? `DELETE: removed appointment ${id}` : `DELETE: no row with id ${id}`);
  return { deleted };
}

export async function assertAppointmentAbsent(sql, id) {
  const rows = await sql`select id from appointments where id = ${id}`;
  const joinRows = await sql`
    select a.addon_service_id from appointment_addon_services a where a.appointment_id = ${id}`;
  const absent = rows.length === 0 && joinRows.length === 0;
  console.log(absent ? `ABSENT: verified — no appointment row, no join rows for ${id}` : `ABSENT: FAIL — rows remain`);
  return { absent };
}

function printUsageAndExit() {
  console.error('usage: node scripts/verify-appointment-row.mjs <confirm|delete|absent> <appointmentId>');
  console.error('  confirm reads expectations JSON from stdin (the POST response body).');
  process.exit(1);
}

if (process.argv[1] && process.argv[1].endsWith('verify-appointment-row.mjs')) {
  const [mode, rawId] = process.argv.slice(2);
  if (!mode || !rawId) printUsageAndExit();
  let uuidOk = true;
  try {
    crypto.randomUUID();
    uuidOk = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i.test(rawId);
  } catch {
    uuidOk = false;
  }
  if (!uuidOk) {
    console.error('invalid appointment id (not a uuid)');
    process.exit(1);
  }
  const sql = postgres(url, { prepare: false, max: 1, connect_timeout: 15 });
  try {
    if (mode === 'confirm') {
      const stdin = await new Promise((resolve, reject) => {
        let data = '';
        process.stdin.setEncoding('utf8');
        process.stdin.on('data', (chunk) => {
          data += chunk;
        });
        process.stdin.on('end', () => resolve(data));
        process.stdin.on('error', reject);
      });
      let expected;
      try {
        expected = JSON.parse(stdin);
      } catch {
        console.error('stdin is not valid JSON (pass the saved POST response body)');
        process.exit(1);
      }
      const result = await assertAppointmentRecord(sql, expected);
      process.exit(result.ok ? 0 : 1);
    }
    if (mode === 'delete') {
      const result = await deleteAppointmentRow(sql, rawId);
      if (!result.deleted) process.exit(1);
      const absent = await assertAppointmentAbsent(sql, rawId);
      process.exit(absent.absent ? 0 : 1);
    }
    if (mode === 'absent') {
      const result = await assertAppointmentAbsent(sql, rawId);
      process.exit(result.absent ? 0 : 1);
    }
    printUsageAndExit();
  } finally {
    await sql.end({ timeout: 5 });
  }
}
```

Design notes for the implementer: `confirm` takes the **saved POST response body** on stdin as its expectations — so the probe asserts the API wrote exactly what it returned (spec Story 3's full row fidelity: identity, Kind, Status, Branch/Package FKs, `packagePriceCents`, scheduledAt, add-on join rows with per-row snapshots). `customerPhone`/`scheduledAt` get separate treatment (phone optional in diff, timestamp compared via ISO round-trip) because Postgres returns a `Date` object whose string form differs from the response's. The `crypto.randomUUID()` probe in the UUID guard is a Node-version sanity latch — if it throws, the runtime is too old; keep it inside the try as written.
