# Seed the v1 branch — the one filter-repo pass (booking-free artifact line) (#80) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce the long-lived booking-free `v1` branch in this monorepo — one `git filter-repo` pass over a fresh clone of `origin/main` (booking-only paths inverted away, embedded shared-file references scrubbed by content rules keyed to the absence inventory, transformed surfaces taking their booking-off content, the api env-shed, the typed-cascade cut through the api-client group, tests following their code, docs scrubbed to the client-safe set, AGENTS.md rewritten client-safe) + one authored seed content commit on top — proven locally (audit zero hits, `pnpm check` + `pnpm build` green, booking-free landing serving from dev) and pushed to origin exactly once, behind an owner sign-off gate, so the pre-landed CI + private deploy fire on the first push.

**Architecture:** Two-layer rewrite, matching ADR-0015's "history rewritten exactly once": (1) a mechanical `git filter-repo` pass (`--invert-paths --paths-from-file` + `--replace-text` + `--replace-message`, all three rule files committed to main for the record at `scripts/seed-v1/`) rewrites ALL history so no blob or commit message anywhere carries the absence-inventory tokens — historical revisions need not typecheck (ADR-0015: "the history is an audit artifact"); (2) ONE hand-authored seed content commit on the rewritten HEAD lands the real booking-off content (per spec § The Booking-Off Direction), the env-shed, the api-client cut, the client-safe docs, and the client-safe AGENTS.md — HEAD always builds and deploys. The audit instrument (#78) is the lineage gate; its two false-positive tokens (`/book`, `/appointments` — both discovered by this ticket's re-verification, AC 1) are re-derived on main FIRST. Local iteration is free (re-clone + re-filter as often as needed); **the origin push of `v1` is the one-way door** and sits behind owner sign-off (AC 6, ADR-0015's irreplacability warning).

**Tech Stack:** git 2.43.0 + `git-filter-repo` (installed via `pipx install git-filter-repo` — Task 3 Step 1; version reports `a40bce548d2c`; its expression files support `literal:` (default), `regex:`, `glob:` prefixes and `#` comment lines), Node ≥ 24 (v26.7.0), pnpm 11.24.0, docker compose (Postgres 17 for the api integration suite), the #78 audit script (`scripts/audit-v1-absence.mjs`, main-only). No new npm dependencies anywhere (one is REMOVED: `resend` from `apps/api`).

**Spec:** `docs/specs/2026-09-11-delivery-versions-spec.md` (GitHub issue #76) — § The v1 Absence Boundary (the inventory), § The Booking-Off Direction (the transformed-surface content), § The Artifact Mechanism (ADR-0015), § Verification. _Avoid_: reservation, order

_Avoid_: ad-hoc state strings ("done", "closed")

_Avoid_: type, mode, channel

_Avoid_: walkinEnabled, acceptsWalkins (in prose)

_Avoid_: size (unqualified), format

_Avoid_: lamination, coating

_Avoid_: outfit, costume, wardrobe (that is the usage Inclusion)

## Engineering Rules

- **Never commit secrets.** `DATABASE_URL`, `BETTER_AUTH_SECRET`, `SENTRY_DSN` are set via `wrangler secret put` per environment, never in `wrangler.toml`/`.env` files that get committed.

- **Database access goes through `packages/db`.** Don't hand-write SQL or open a second Postgres client elsewhere. Schema changes are Drizzle migrations, generated via `db:generate`, never edited by hand in `packages/db/migrations`.
- **Keep route handlers thin.** In `apps/api`, business logic belongs in a service/module, not inline in the Hono route. Routes: parse/validate input, call a function, return a response.
- **Use `async`/`await`** exclusively; avoid raw Promise chains or callbacks.
- **Each app owns its UI**, but shared tokens live in `packages/ui` (shadcn CSS variables). Apps are Tailwind v4 (CSS-first) — theme via `@theme` in each app's `styles.css`; don't duplicate token definitions between `landing` and `admin`.

- **Log decisions.** Any nontrivial architectural choice (e.g. how auth sessions are shared across `landing`/`admin`/`api`, or how R2-stored images are served) gets an ADR in `docs/adr/`. Numbering gaps in the ADR directory are known and accepted.
