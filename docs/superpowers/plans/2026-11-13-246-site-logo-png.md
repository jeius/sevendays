## Design (one paragraph, pinned before Task 1)

The presign vocabulary moves from one flat content-type enum to **per-purpose allowed
types**: `site-logo` allows `image/jpeg | image/png`; the other three purposes allow
`image/jpeg` only. `mediaPresignRequestSchema` becomes a union of two literal-purpose
objects so the pair (purpose, contentType) is validated in one schema. The staging-key
regex widens to `\.(jpg|png)$. The commit gate derives its allowed set from
`input.purpose` and stamps the final-key extension from the stored content type
(`.png` for PNG) instead of the hardcoded `.jpg`. The byte cap is one shared constant
moved to its owner-ratified value; both the api service and the admin pre-check import
the number from `@sevendays/types` so the courtesy check and the real gate cannot drift.
