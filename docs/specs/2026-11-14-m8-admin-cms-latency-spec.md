# M8 — Admin-CMS Latency Spec

*Drafted 2026-11-14 from wayfinder map [jeius/sevendays#279](https://github.com/jeius/sevendays/issues/279) — the four resolved decision tickets ([baseline #280](https://github.com/jeius/sevendays/issues/280), [session amortization #281](https://github.com/jeius/sevendays/issues/281), [thumbnail serving #282](https://github.com/jeius/sevendays/issues/282), [topology #283](https://github.com/jeius/sevendays/issues/283)) plus the owner rulings locked at charting. Status: **RATIFIED by the owner, 2026-11-14** (grill on [ticket #284](https://github.com/jeius/sevendays/issues/284)).*

## Problem Statement

Staff use the admin from the Philippines against a Supabase project in Singapore, and every screen makes them wait as if they were the first person ever to touch the database. A baseline walk (2026-11-14, ticket #280) measured every CMS list read at **2.5–5.0 s wall clock** (median 2.65 s), with cpuTime of only 14–39 ms — about 99% of the wait is database I/O. Warm revisits after the client's 60-second freshness window are **just as slow as cold ones** (the packages read: 5.0 s cold, 5.0 s warm median), because every request pays the same per-request costs: a fresh Supavisor connect over a cross-ocean round-trip chain (the api worker executes at the user's colo, not the DB's), a session verification that queries Postgres before the entity query runs, and — on the gallery — the same penalty again per thumbnail (11 photos cost 41 seconds of cumulative wall time). Moving between screens feels like the site is broken; nothing about the content is slow, only the waiting.

## Solution

Set and enforce a **Warm/Cold Navigation contract** (terms per the admin glossary): **Warm Navigation** — any screen whose data the client already holds — renders instantly from cache with a background refetch behind it; **Cold Navigation** — the first visit in a session — shows a skeleton immediately and fetches against a server that no longer pays three taxes per request. The four levers, all decided on the map:

1. **Place the api worker in the DB's metro** (Singapore) so fresh Supavisor connects and queries run intra-region instead of Manila→Singapore. Modelled saving ~150–600 ms per cold read; the measured baseline suggests the episodic connect-degradation share is even larger.
2. **Amortize session verification on both halves** (60 s TTL, the owner-ruled bound): the admin shell gate serves `getSession` from BetterAuth's signed cookie cache; the api's session gate serves a token-hash→(session, user) read-through cache over the Workers Cache API. A revoked session may pass both gates for ≤60 s per colo — the ruled trade.
3. **Serve gallery thumbnails as versioned immutable URLs** with `private, immutable` caching, so a warm grid makes **zero** network requests and a re-upload can never show an old thumb (structural invalidation via the commit contract's fresh keys).
4. **Honor the Warm/Cold contract in the client**: five-minute staleness on CMS queries (background-refetch semantics — bounded staleness, per the ruling), intent-time data prefetch so Cold Navigations start earlier, and the already-wired own-mutation invalidation preserved as an invariant.

Then prove it: the exit gate re-runs the #280 baseline method and compares per-route cold medians against the table in that ticket.

## User Stories

1. As a Staff User, I want Warm Navigation between CMS screens to render instantly from what I already have, so that moving around the admin never feels like waiting on the network.
2. As a Staff User, I want Cold Navigation to show a skeleton immediately, so that even a first visit feels responsive before the data lands.
3. As a Staff User, I want my own saves to appear immediately after Save succeeds, so that I never see a stale row I just edited.
4. As a Staff User, I want background refetches to happen behind rendered content and never block a screen, so that freshness never costs me a spinner.
5. As a Staff User, I want the packages screen to load in a fraction of its current ~5 s, so that price and content edits don't stall mid-workflow.
6. As a Staff User, I want list filtering and search to stay client-side after load, so that the latency work never adds per-keystroke round trips.
7. As a Staff User browsing the gallery, I want thumbnails I've already seen to render from my browser instantly, so that revisiting the grid costs nothing on the wire.
8. As a Staff User uploading a replacement photo, I want the new image to be the only one anyone can see, so that a stale thumb can never resurface after a re-upload.
9. As a Staff User, I want sign-out to end my session immediately in my browser, so that shared-device security holds even while other caches live for seconds.
10. As an Owner, I want a deactivated or demoted staff member's token to stop passing the API's gate within one minute, so that the speed-up doesn't materially weaken access revocation.
11. As an Owner, I want the Audit Log and Users screens to keep their exact freshness and role-gating semantics, so that owner-scoped correctness is never traded for speed.
12. As an Owner, I want a post-milestone re-run of the baseline walk to show per-route cold medians materially below the 2.5–5 s baseline, so that M8 is proven with numbers, not vibes.
13. As an Owner, I want no paid-tier dependency introduced by this work, so that the speed-up adds zero cost.
14. As an Owner, I want the public landing's cache behavior change (its edge cache warming in Singapore instead of Manila) acknowledged and accepted, so that the trade is on the record.
15. As an implementer, I want the api session cache to reuse the existing read-cache seam pattern with a null store under vitest, so that all api suites stay uncached and deterministic.
16. As an implementer, I want the session-amortization and placement decisions recorded in ADRs, so that a future reader understands both the mechanism and the ruled bounds.
17. As an implementer, I want per-query staleness to live in the shared CMS query factories, so that the Warm/Cold contract is enforced in one place rather than per screen.
18. As an operator, I want the placement change verified through the `cf-placement` response header and the existing access-log durations, so that no new tracing or observability cost is introduced.
19. As a Staff User, I want the submission moderation actions (accept / reject / delete) to answer as fast as the rest of the CMS, so that the daily moderation loop doesn't stall.
20. As a Staff User, I want all of this to behave identically in light and dark themes with no visual changes beyond skeletons and spinners, so that the milestone touches only time, not pixels.

## Implementation Decisions

**D1 — Region placement of the api worker (topology verdict #283).** Pin the api worker to the database's metro with a region placement hint (`[placement] region = "aws:ap-southeast-1"`) in its wrangler config — region mode, **not** Smart Placement (smart mode only considers colos the worker has already run at; Singapore is not among them, and admin-only volume would starve its analyzer). The frontends stay at the edge: placing them would add a cross-metro hop to every page. This composes with the existing topology decisions — the service-binding call path (ADR-0016) forwards one extra hop (~30–70 ms) in exchange for intra-metro database access; the per-request fresh connect (ADR-0011, Supavisor transaction mode) stays as-is. Acknowledged side effect: the public read cache (ADR-0025) will warm in Singapore; warm public reads from PH pay a small forward-hop while cold ones save more — net favorable, landing is out of scope. One new ADR records the decision and the Hyperdrive history (the failed attempt, ADR-0024, stays burned; the #260 recipe stays parked).

**D2 — Session-verify amortization, both halves (research verdict #281).** The two halves are independent; build both.

- *Admin half:* enable BetterAuth's session cookie cache on the admin's auth instance with the ruled bound (`cookieCache: { enabled: true, maxAge: 60 }` — the library's 300 s default must be overridden to honor the ruling). A hit serves the shell gate's `getSession` from the HMAC-signed session cookie with zero database I/O; the token cookie is still signature-verified first. Known failure mode to pin: the framework's cookie adapter can silently fail to set the cache cookie, degrading to today's per-navigation database read — a performance-only degradation that the milestone's verification step must actively check (the cookie actually lands from the sign-in flow).
- *API half:* a new session-cache service beside the existing read-cache service in the api, cloning that service's injectable-store seam. The session gate consults a token-hash → (session, user) read-through cache over the Workers Cache API before performing today's verification; misses verify and back-fill. Key = SHA-256 over a secret fingerprint plus the bearer value — never the raw token in a key or a log; 401 outcomes are never cached; a hit re-checks the cached session's expiry. The null-store default keeps every vitest suite uncached, matching the read-cache law. All cache I/O is best-effort per the ADR-0025 precedent.
- *Revocation is TTL-only by design* (owner-ruled): every revocation path (sign-out, ban, user removal, session revoke, password reset) deletes the session row on the admin's auth server; none executes inside the api, so no cross-app eviction hook exists. Bound: a revoked/expired session may pass both gates for ≤60 s per colo; the signing-out browser itself is immediate (cookies cleared). One new ADR records the mechanism and this bound; the M4 spec's "measure before adding machinery" deferral is discharged by the #280 baseline.

**D3 — Thumbnail serving (research verdict #282).** Keep the thumb proxy's path and auth model; make its responses cacheable and its URLs versioned. The gallery grid requests thumbnails through a tiny client-side builder that appends the photo's last-updated timestamp as a version query parameter (the field already rides the admin wire, so no API or shared-schema change). The proxy answers 2xx with `Cache-Control: private, max-age=31536000, immutable` and no-store on error arms — superseding the earlier no-cache ruling (#136), which the milestone's ADR-adjacent note records. Invalidation is structural: a replace mints a fresh storage key and bumps the timestamp in the same transaction, and the old object is deleted post-commit (ADR-0019 flow), so the old URL can never be re-derived and a stale-tab request for it 404s at origin. Grid images also gain `decoding="async"`; lazy-loading is already present. CF Images direct-serve was considered and rejected (the binding transforms but does not deliver; its delivery URLs are public/unsigned on a shared CDN — a privacy posture the ruling doesn't cover). Admin-local only; the api is untouched by this lever.

**D4 — The Warm/Cold contract in the client (owner ruling, map Notes).** The shared CMS query factories carry a five-minute staleness for CMS list/detail queries (the Analytics dashboard and Audit Log keep their own tuned values — out of scope). Within staleness, TanStack Query's default behavior already renders cached data instantly — that is Warm Navigation; a background refetch follows on mount-after-stale. Data prefetch moves earlier: CMS routes gain loader-time cache priming (the shell's site-settings priming is the in-repo precedent), so a hover-intent navigation starts the fetch before the click and Cold Navigations shorten. Own-mutation invalidation is **already wired** across the CMS screens (packages, testimonials/submissions, lookups, and the settings flows) — this spec pins it as an invariant to preserve, not new work. The ruled staleness bound: nothing shown is more than five minutes behind; a background refetch always follows; cross-staff edit lag up to that refetch is accepted.

**D5 — Measurement stays cheap (standing ruling).** No Sentry trace re-enable. Phase attribution, if wanted later, rides Server-Timing-style response metadata; M8's proof is the exit gate (below), which needs only the access log and the tail method that already exists.

**D6 — Exit gate (graduated fog; method per ticket #280).** Re-run the #280 baseline walk post-M8 (same method: supervised tail + owner cold/warm walk) and compare per-route cold medians against the baseline table. Ratified target: **cold median ≤ 1 s per admin read** (from 2.65 s), **Warm Navigation at zero network wait** (client-side by construction), thumb flood eliminated (warm grid = 0 requests). Commit-green and smoke-green stay separate verdicts (ADR-0022) — the exit gate is operational, never part of `pnpm check`.

**D7 — Charter math.** Estimated ticket split: placement + verify (1), api session cache + ADR + tests (1), admin cookie cache + verification (1), thumbnails (1), client contract — staleness + loaders (1–2), exit-gate re-run (1). That is 6–7 tickets, above the ≤2 threshold, so **M8 charters as a milestone** (conditional charter per the map's Destination). Handover renumbers **M8 → M9** — the third bounded renumber in the plan's history (after the M3 and M7 seatings), justified by the delivery-versions rule that v1 hands over only once the polish milestones land: a 2.5–5 s-per-screen admin is not the handover artifact. The `docs/plan.md` amendment — the new M8 section, the re-annotated Handover header, the amended v1-sequence line — happens at the `/to-tickets` charter step.

## Testing Decisions

A good test here pins externally observable contracts, not internals: what a caller gets from a seam, never how the seam is wired inside.

- **API session cache (new tests, existing seam pattern):** mirror the read-cache seam suite — a fake store asserting hit/miss/back-fill, key construction without the raw token, 401-never-cached, expiry-guard-on-hit, and — deliberately — the *revoked-row-passes-within-TTL* contract pinned as the ruled behavior, so the bound is visible in the suite rather than folklore. Prior art: the #263 read-cache seam pins. The null-store default keeps the existing 460+ api tests uncached by construction.
- **Admin thumb builder (new tiny seam, house pattern):** a lib-seam test over the URL builder (version param derivation from the wire shape) and the header constants (immutable on 2xx, no-store on error). Prior art: the admin lib-seam floor.
- **Client contract (existing seams, new pins):** staleness values asserted against the shared query factories' returned options (pure-object assertions), and loader-time priming asserted at the same seam if extractable; per the house rule there are no component/DOM tests.
- **Admin cookie cache:** the configuration object is pinned (the ruled 60 s override); the silent-unset-cookie failure mode is verified operationally in the milestone (the cookie lands from sign-in), not unit-tested.
- **Placement:** not unit-testable — verified operationally via the `cf-placement` header plus before/after access-log durations; the exit-gate re-run is its acceptance test.

## Out of Scope

Per the map's Out of scope section, all owner-ruled: pagination/payload shrinking; the Appointments worklist (v2 stub); the Analytics dashboard (already tuned); Hyperdrive re-land (parked in #260's recipe); Sentry trace re-enable (CPU-cap ruling); public/landing reads (already edge-cached, ADR-0025). Additionally proposed here: the **admin-worker → database-direct reads** (Audit Log viewer, Users tab, the shell gate's own session check) keep their cross-metro connect penalty — the placement lever cannot reach them and the cookie cache only removes their session-verify share; as owner-only, low-frequency screens they are **ratified as an accepted residual** (owner ruling, 2026-11-14).
